Network policy — enforced, not promised

The environment's only connected component runs a kernel firewall whose default action is drop: anything not listed below cannot leave, and the enclave itself has no route out at all. 6 destinations are permitted.

  1. ct state established,related accept
  2. oifname "lo" accept
  3. ip daddr 104.16.0.0/12 tcp dport 443 accept
  4. udp dport 53 accept
  5. tcp dport 53 accept
  6. ip daddr 160.79.104.10 tcp dport 443 accept

What this demo assumes: the coding agent and its model are the customer’s own — REACHABLE drives whatever agent the enclave already has. A future product phase could bundle a coding agent + REACHABLE + a local LLM as a single turnkey installation; that is not what we are demonstrating today.

Keys: this demo self-generates its mirror and enclave-host keys for the Sthenos-owned demo org (a CI preflight-auth step, regenerated on demand). A real customer generates theirs through the dashboard — in the browser, so the private key never leaves them, or as short-lived temporary test credentials — needing only a single firewall hole to sthenosec.com, never internet access.

Trust & cryptography: software is admitted into the enclave only from a CNSA-aligned, post-quantum signed attestation; the connection to Sthenos is a mutually authenticated (mTLS) channel; data is encrypted at rest. The highest-assurance trust anchor sits exactly where it matters — on the code entering the air-gapped boundary.
